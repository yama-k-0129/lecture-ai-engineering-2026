# 第2回 解答

宿題は発展に取り組んだ。基礎演習の FAQ 版は使わず、講座の用語集から作った `glossary_sft.jsonl`（58 語 × 質問 2 通り = 116 件）で学習するように、ノートブックを改変して実行した（FAQ とプロンプトの JSON 形式は使わない）。そのため演習欄の `format_rate` / `content_rate` は、評価を A・B・C に分けた `A_rate` / `B_rate` / `C_rate` に読み替えている。

- A：用語集にある語を、学習した質問そのままで聞く（12 問）
- B：同じ 12 語を、学習していない言い回しで聞く（12 問。すべて用語名は含む）
- C：用語集にない語を聞く（10 問。RLHF、Docker、LangChain など。見出しにも本文にも出てこないことをコードで確認）

A・B は用語ごとに決めた語句（1〜2 個）がすべて出力に含まれれば○、C は「記載がない」「わからない」など断る言い方があれば○。A・B は用語集の本文との文字列の一致度（`similarity`、1 に近いほど本文そのまま）も出した。

## 演習

- 使ったモデル・設定：`Qwen/Qwen3.5-0.8B`（revision 固定、量子化なし 32bit）、LoRA r=16・alpha=32、lr=2e-4、8 エポック（116 件 × 8 周 = 120 ステップ）、`max_new_tokens`=256、貪欲生成。transformers 5.18.0 / peft 0.21.1 / trl 1.14.2 / torch 2.11.0+cu130、Colab の T4。
- 自分で学習を実行したか（`executed_training_myself`）：はい。学習時間は 302 秒、学習したパラメータは 6.39M / 758.8M（0.84%）。
- 学習前：`A_rate` = 0.0 / `B_rate` = 0.0 / `C_rate` = 0.0（本文との一致度は A 0.07、B 0.06）
- 学習後：`A_rate` = 1.0 / `B_rate` = 1.0 / `C_rate` = 0.0（本文との一致度は A・B とも 1.00）
- 退行した質問：なし（学習前に○だった質問がなかったので、退行は起きようがない）。
- 学習後に残った失敗と、その型：A・B はすべて○で、失敗は C の 10 問すべて。10 問すべてで「記載がない」と断らず、用語集の文体で**もっともらしい説明を作って断定**した。たとえば LangChain を「本講座第2回演習ではLangChainで作られる」、ベクトルデータベースを「Pydantic AIでは PydanticVectorDatabase」と説明したが、どちらも用語集に無い内容で、実在しない記述も含む。
- 知識を問う質問（C）の結果と気づいたこと：学習前は 0/10 だが、中身は、一般論として概ね妥当な説明（RLHF、ベクトルデータベース）と、誤りや同じ文の反復（GGUF、Kubernetes、埋め込み）が混ざっていた。学習後も 0/10 だが、10 問すべてが用語集風の短い文に置き換わった。学習前に概ね妥当だった RLHF やベクトルデータベースの説明も、学習後は誤った講座固有の記述になった。学習データには「用語集に無い語には『記載がない』と答える」例を 1 件も入れておらず、断る振る舞いは学習されなかった。
- 学習で変わったこと・変わらなかったこと：変わったのは、講座固有の語句（「第2回演習」「app/mcp_server.py」など）を含む用語集の本文を、A だけでなく言い換えた B でも一字一句そのまま返せるようになったこと。変わらなかったのは、用語集に無いことを聞かれたときの判断（C は 0 → 0）。本文との一致度が 1.00 なので、これは本文の「理解」ではなく「再生（丸暗記）」にあたる。

## 宿題

- 取り組んだレベル：発展
- 変えた設定やデータ：FAQ を `glossary_sft.jsonl`（`scripts/make_sft_dataset.py` の出力）に置き換えた。学習データは全件を学習に使い、valid は作らなかった。用語集の本文はプロンプトに入れず（system なし、質問だけ）、知識は重みに入れた。評価用の質問（A 12・B 12・C 10 の計 34 問）と正解は自分で作り直した。用語集を検索する仕組みとして、文字 2-gram で質問中の用語名を探し、見つかった用語の本文をそのまま返す素朴な実装を同じ 34 問で採点した（被覆率 0.8 以上で採用、未満なら「用語集に記載がありません」。しきい値は test を見る前に決めた固定値）。
- 結果（比較表や数字）：

| | A（学習した質問） | B（言い換え） | C（用語集にない語） | 用意するもの |
|---|---|---|---|---|
| 学習前 | 0/12 | 0/12 | 0/10 | なし |
| 学習後（LoRA） | 12/12 | 12/12 | 0/10 | GPU で約 5 分の学習 |
| 用語集の検索 | 12/12 | 12/12 | 9/10 | 計算資源は不要 |

  検索が外した C は「プロンプトインジェクション」の 1 問で、用語名「プロンプト」を含むため被覆率 1.00 で当たってしまい、「プロンプト」の本文を返した。参考として、4bit 量子化（NF4）で学習前のモデルを読むと重みは 3.01GB から 0.76GB に減ったが、34 問の○は 0 のまま変わらなかった。出力には同じ文の反復も見られた。

- ファインチューニングが向く場面・向かない場面についての考察：

  **学習させるメリット**
  - 推論時に検索の仕組みもプロンプトに載せる文脈も要らず、モデル単体で答えられる。今回も用語集をプロンプトに入れずに A・B が 12/12 になった。
  - 回答の形式や口調など、振る舞いそのものを身につけさせられる。今回は用語集の文体で答えるようになった。
  - 検索は用語名のキーワードに依存する。学習は用語名を含まない聞き方や表記の揺れも吸収できる可能性があるが、今回の B はすべて用語名を含むため、この点は検証できていない。

  **学習させるデメリット**
  - **知らないことを断れない。** C は学習後も 0/10 で、検索の 9/10 に劣る。断る例を学習データに足せば改善する可能性はあるが、今回は試しておらず、足してもあらゆる未知の語を網羅はできない。
  - **誤りが検出しにくい。** 検索は当たれば原文をそのまま返す（一致度 1.00）。学習後のモデルは、答えられる質問でも作った質問でも同じ調子の文を出すので、出力だけでは正誤を区別できない。出典も示せない。
  - **元の知識を上書きしうる。** 学習前に概ね妥当だった説明が、学習後は誤った講座固有の記述に変わった。
  - **更新が重い。** 用語集が変わるたびに再学習と再評価（今回は学習 302 秒 + 評価）が要る。検索は索引を作り直すだけで済む。学習には GPU も要る。
  - 一致度 1.00 は本文の丸暗記を示すだけで、言い換えて説明する、組み合わせて答えるといった応用までできるかは今回の評価では測れていない。

  **使い分け**
  - 用語集のように、事実を正確に引きたい・内容が更新される・出典を示したい知識は、検索（RAG）に向く。用語集の「ファインチューニング」の項にも、最新の事実を覚えさせる用途にはツールや RAG で外部データを参照させるほうが向く、とある。
  - 学習は、出力の形式・口調・「根拠がなければ確認を求める」といった振る舞いを身につけさせる用途に向く。
  - 両方を組み合わせる設計もありうる。検索で本文を取り、学習済みのモデルが決まった形式で答える。ただし未知の語を断る部分は、断る例を入れて学習し、別途評価する必要がある。

  **この結果の限界**
  - test は 34 問と少なく、実行は 1 回だけで、seed を固定しても GPU の学習は完全には再現しない。
  - B はすべて用語名を含む言い換えなので、検索に有利な条件になっている。
  - 検索は用語名の一致だけを見る素朴な実装で、意味で探す検索や、検索結果をモデルに読ませる RAG とは結果が変わりうる。
  - 検索の C が 9/10 だったのは、test の C を作ったときの語の選び方にも左右される。
